## Decisions Made

- **MMB pan accepts the Phase 5 bridge-abort cohabitation as v1 behavior.** Documented in `xvue_qt_canvas.cpp` file header. The Qt event order `eventFilter -> canvas handler` means Phase 5's `XvueEventBridge::eventFilter` sees the MMB press first; when `loop_ != nullptr` (Souris mode active), the filter eats the event with `notypeevent=0, nbc=2` (abort path) and the canvas pan handler never runs. When `loop_ == nullptr` (idle), the filter passes through and the canvas owns the pan gesture. Plan 03's A6 audit gates the v1.x decision on whether to keep dual-mode or migrate to Ctrl+MMB.
- **Empty-state hint always calls drawText even when xvueT() returns empty strings.** Plan 01's i18n scaffold returns `""` for every MsgId; if we conditionally skipped drawText on empty content, the `lastPaintDrewEmptyState_` test observable would never fire and Plan 02's filling of the FR/EN table would silently change test outcomes. Always calling drawText keeps the test deterministic and Plan 02's translation work purely additive.
- **Test observability counter `contextMenuShownCount_` bumps even when the menu is empty.** Separates the "menu would-be-shown" gating decision (which Plan 05 owns and tests) from the "populator returned content" decision (which Plan 04 owns and tests).
- **Context menu populator wiring deferred to Plan 02.** The `XvueWindow::menuBridge()` accessor doesn't exist yet (Plan 02 adds it). The contextMenuEvent body has the integration site stubbed with a `(void)win` cast and an explanatory comment so a single `git grep`-able marker leads the next plan to the right place.
- **Test target `xvue_qt_canvas_gestures_tests` added provisionally in this worktree's `tests/CMakeLists.txt`.** Plan 05 frontmatter explicitly states "tests/CMakeLists.txt additions for this plan's test binary are owned by Plan 02 to avoid Wave 2 parallel-worktree merge conflicts." Adding it here lets local verification proceed; the orchestrator's merge of Plan 02 + Plan 05 will reconcile (Plan 02 ships the canonical version of the same target — both edits are functionally equivalent).
