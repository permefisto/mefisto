## Accomplishments

- **Console dock real stdout capture.** `installStdoutRedirect()` does the full POSIX dance per RESEARCH §3: `pipe()`, then `fcntl(fd[0], F_SETPIPE_SZ, 1<<20)` to expand the pipe buffer to 1 MB (T-06.0-CONSOLE-01 mitigation), then `dup2(fd[1], STDOUT_FILENO)`, then `setvbuf(stdout, NULL, _IOLBF, 0)` AFTER the dup2 (RESEARCH Pitfall 3.4 — order matters), then a `QSocketNotifier(fd[0], QSocketNotifier::Read, this)` connected to `onPipeReadable`. Idempotent guard via `readFd_ >= 0` short-circuit prevents double-redirect leaking the previous pipe. Pipe write-end fd is intentionally not closed at dtor time (would invalidate the dup'd STDOUT_FILENO that Fortran is still using; mirrors Phase 1 D-08's leak-the-QApplication discipline).
- **Line-splitting parser shared between live and test paths.** `drainPartialLineBuffer()` is the single source of truth — `onPipeReadable()` and the test-only `feedRawBytesForTest()` both append into `partialLine_` and call into it. Splits on `'\n'`, appends each completed UTF-8 line via `appendLine()` (which auto-scrolls to bottom), and forwards lines starting with `*** ERREUR` or `*** ERROR` to `errorBatcher_->enqueue()`.
- **Error batcher 500 ms cascade collapse.** `XvueErrorBatcher::enqueue` arms a single-shot `QTimer` only if not already active, so N lines arriving within `kBatchWindowMs` collapse into ONE `QMessageBox::warning` whose body is the lines joined by `'\n'` (T-06.0-04-01 mitigation). `flushErrorBatch` checks `XvueApp::blockingDepth() > 0` before firing — if Fortran is currently inside a nested `xvsouris_` wait (Phase 5 D-03), the timer is re-armed for another window and the pending lines stay in place, mitigating T-06-03-01. The actual `QMessageBox::warning` is fired via `QMetaObject::invokeMethod(qApp, lambda, Qt::QueuedConnection)` so we exit the timer's slot stack frame before the modal `exec` begins.
- **About dialog with positional substitution.** `XvueAboutDialog::show(parent)` calls `QMessageBox::about(parent, AboutTitle, AboutBody.arg(MEFISTO_VERSION).arg(qVersion()).arg(__DATE__))`. The `MEFISTO_VERSION` macro is defined in `xvue_qt_about_dialog.cpp` behind `#ifndef` with default `"v1.0-qt6"` so a future Plan 06 versions header can override via `-D` without source edit.
- **Preferences dialog single-panel form.** `QFormLayout` with three rows (color-scheme `QComboBox` with System/Light/Dark items keyed by user-data string, console-default `QCheckBox`, recent-count `QSpinBox` 1–20 disabled v1 placeholder) plus a `QDialogButtonBox(Ok|Cancel)` whose buttons are re-labeled via `xvueT(ButtonOk)/xvueT(ButtonCancel)`. `onAccept` writes `XvuePrefs::saveColorScheme` and `XvuePrefs::saveConsoleVisible`; the recent-count value is intentionally NOT persisted (placeholder; XvuePrefs::pushRecentProject hard-codes the 10-entry cap).
- **Recent projects submenu with destructive-confirm.** `refresh()` builds one `QAction` per `XvuePrefs::recentProjects()` entry (label = `QFileInfo::fileName()`, tooltip = full path) connected to a `[this, path]` lambda emitting `openProjectRequested(path)`. Empty list shows a disabled `"(none)"` placeholder so the submenu is never empty. Always-visible "Clear Recent" action guards a `QMessageBox::question(parent, FileRecentClearConfirmTitle, DestructiveConfirmBodyGeneric, Ok|Cancel, Cancel)` — only `Ok` triggers `XvuePrefs::clearRecentProjects() + this->refresh()`. Default = Cancel = safe per UI-SPEC §Destructive actions.
- **11-case QTest suite source landed.** `test_xvue_qt_dialogs_console.cpp` covers: `appendLine` smoke, `setMaximumBlockCount` cap, partial-line buffering, no-redirect-no-crash, single-line batcher fires, 3-line cascade collapses to 1 box, deferred-during-`BlockingDepthGuard` defers then fires after scope exit, About dialog body intercept, Preferences round-trip Ok-saves, Preferences Cancel-discards, Recent Projects population (>=3 actions), Recent Projects signal emission. The source file lives in `xvue/qt/tests/` waiting to be picked up at merge.

## Decisions Made

- **`feedRawBytesForTest` is a public-but-undocumented method, not `#ifdef XVUE_QT_TESTING`-gated.** The plan's `<action>` recommended the simpler form; an `#ifdef` would require the test binary to define a matching `-D` flag, doubling the API-drift surface for marginal encapsulation gain. The method is documented as "test hook" in both the header doc-comment and the .cpp body comment.
- **Single-line `drainPartialLineBuffer()` helper extracted.** The plan's `<action>` showed two near-duplicate parsing loops in `onPipeReadable` and `feedRawBytesForTest`. Extracting one helper avoids the obvious bit-rot risk where one branch grows a feature (e.g., ANSI-color stripping in a future plan) and the other doesn't. Functionally equivalent to the plan's spec.
- **`QMessageBox::warning` fired via `QueuedConnection` rather than directly in `flushErrorBatch` slot.** Direct invocation would mean the modal exec begins inside a `QTimer::timeout` dispatch, which is the same trap T-06-03-01 cautions against in the nested-xvsouris context. Queued-invoke breaks the stack and lets the timer slot complete first. Plan's `<action>` already specified this pattern; documenting the rationale.
- **Deferred-during-blocking re-arms the existing timer (`timer_->start()`).** Pending lines stay in `pendingErrorLines_` across the wait, so once the blocking call ends and the next 500 ms window fires, the FULL backlog appears in one `QMessageBox`. This is strictly better than dropping the lines or firing one box per deferred attempt.
- **`MEFISTO_VERSION` macro local to `xvue_qt_about_dialog.cpp` with `#ifndef` guard.** Default `"v1.0-qt6"` per the plan. Plan 06 (or any later plan) that wants a centralized versions header can `target_compile_definitions(xvueqt PRIVATE MEFISTO_VERSION="v1.1-qt6")` without touching this file. Documented as a hand-off in the file's header comment.
- **Recent-count `QSpinBox` ships disabled (setEnabled(false)) — v1 placeholder.** Documented in the source comment + the SUMMARY's "Known Stubs" section. UI-SPEC §Preferences requires the control for layout conformance, but `XvuePrefs::pushRecentProject` currently hard-codes the 10-entry cap. Wiring the user-configurable cap through is a future-plan deliverable; not in Plan 04 scope.
- **Empty-list placeholder is `tr("(none)")` (Qt's runtime tr, not `xvueT`).** UI-SPEC's MsgId enum doesn't have an `EmptyRecentPlaceholder` entry. Using `tr()` keeps the placeholder localizable later via Qt's standard mechanism without forcing a Plan 02 enum-table edit. Documented inline.
- **Test target wiring deferred to Plan 02.** Per the plan's frontmatter `<files_modified>` note (lines 14-16) and the iteration-1 plan-checker fix (commit `a528e0f` — "Wave 2 CMakeLists single-ownership"), Plan 04 does NOT touch `xvue/qt/tests/CMakeLists.txt`. The test source file lives in the right directory; Plan 02's worktree adds the `add_executable(xvue_qt_dialogs_console_tests test_xvue_qt_dialogs_console.cpp)` line so the orchestrator merge has zero conflict.
