```cpp

// synthetic lexicon character, return it as notypeevent=2 BEFORE entering the
// nested event loop. Drains one char per waitForEvent call — matches Fortran
// SACLAV's one-char-per-read contract (06.0-RESEARCH.md §6).
//
// GUARD: Souris mode ONLY. xvsouris2_ (Souris2) is the accrochage/picking path
// where the Fortran caller expects button/key/motion events with tracking of a
// nearest item — injecting a synthetic menu char mid-picking would short-circuit
// the accrochage state machine (see 06.0-RESEARCH.md §6 Pitfall: "Souris2 does
// NOT expect typed chars; its contract is explicit mouse/key events"). xvpause_
// (Pause) similarly blocks on a specific key-press gate (Phase 5 D-06); menu
// chars would bypass that. Both modes wait for the normal nested loop; a queued
// menu char is deferred until the next xvsouris_ call (standard Souris mode).
//
// Ordering: AFTER BlockingDepthGuard (so ~guard still decrements on early
// return), AFTER save-restore + per-call-state reset (so ~dtor restores outer
// call's state), BEFORE constructing `loop` (we never enter loop.exec()).
// Research §1 "Interaction with AUTOEXIT": pre-drain runs BEFORE AUTOEXIT
// short-circuit — AUTOEXIT is a test escape hatch; a test that queues chars
// wants to see those chars first.
//
// WARNING: The saved_* restore block below DUPLICATES the end-of-function
// restore block (search for `// --- end-of-function restore ---` tag).
// Any future addition to XvueEventBridge's per-call mutable state (e.g., a new
// tracking field in Souris2) MUST be mirrored in BOTH restore sites or this
// early-return path will leak stale state into the outer (caller's) waitForEvent
// frame. This is the only known duplication in the Phase 5+6 bridge. Long-term
// refactor: extract into a `SavedWaitState` helper struct with save()/restore()
// methods — deferred as out-of-scope polish for Phase 6.0.
if (mode == WaitMode::Souris) {
    if (auto& win = XvueApp::window_slot()) {
        if (auto* mb = win->menuBridge()) {
            if (auto c = mb->popChar()) {
                pending_.notypeevent = 2;
                pending_.nbc         = static_cast<unsigned char>(*c);
                pending_.x           = canvas_ ? canvas_->mapFromGlobal(QCursor::pos()).x() : 0;
                pending_.y           = canvas_ ? canvas_->mapFromGlobal(QCursor::pos()).y() : 0;

                if (debug_logging_enabled()) {
                    std::fprintf(stderr,
                        "[xvsouris] mode=%d notypeevent=2 nbc=%d "
                        "x=%d y=%d motion_count=0 depth=%d [menu-pre-drain]\n",
                        static_cast<int>(mode), pending_.nbc, pending_.x, pending_.y,
                        XvueApp::blockingDepth());
                    std::fflush(stderr);
                }
                Result r = pending_;
                // --- early-return restore (MIRROR of end-of-function restore) ---
                loop_         = saved_loop;
                mode_         = saved_mode;
                pending_      = saved_pending;
                quit_pending_ = saved_quit_pending;
                motion_count_ = saved_motion_count;
                items_        = saved_items;
                pmin0_        = saved_pmin0;
                return r;
            }
        }
    }
}
```

**NOTE on `emit`:** Qt's `emit` is just a macro (no-op compiler hint). Calling a signal from outside the emitting class is normally fine because signals are auto-generated as public methods by moc. However, in Qt 6.4+ there's a deprecation warning for calling a signal from outside its class. If the compiler warns, change the emit line to invoke a friend-protected method OR add `XvueEventBridge` as a friend of `XvueCanvas` (Plan 05 declares this friendship). Plan 05's `XvueCanvas` must declare `friend class XvueEventBridge;` in its class body for this emit to compile clean. The friendship is documented in Plan 05's interface contract.

```cpp
        QCoreApplication::processEvents();
        QVERIFY(spy.count() >= 1);
        QCOMPARE(spy.first().first().toPoint(), QPoint(42, 84));

        qunsetenv("MEFISTO_XVSOURIS_AUTOEXIT");
    }
```
