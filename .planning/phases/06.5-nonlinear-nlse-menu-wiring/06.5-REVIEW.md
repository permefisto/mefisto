## Info

### IN-01: Toolbar pointer dereferenced before any null-check

**File:** `xvue/qt/src/xvue_qt_nlse_actions.cpp:451`
**Issue:** Line 451 calls `tb->addSeparator()` directly, while the helper at line 144 (`addToolbarByLexicon`) intentionally returns early on `!tb`. The two patterns are inconsistent: if `XvueWindow::toolBar()` ever returned `nullptr` (it currently cannot — `toolBar_` is built in the ctor's `buildToolBar()` and never reset), the bare `addSeparator()` would dereference null while the helper-driven calls below would silently skip. Same pattern was carried verbatim from the 6.4 ther slice.
**Fix:** Wrap the toolbar block in an `if (tb)` guard for symmetry with the helper, OR drop the helper's null-check (since the contract is "tb is always non-null per XvueWindow invariant"). Recommended:
```cpp
if (tb) {
    tb->addSeparator();
    addToolbarByLexicon(tb, nonlinearMenu, QStringLiteral("2;"));
    addToolbarByLexicon(tb, nonlinearMenu, QStringLiteral("5;"));
    if (auto* viewMenu = mbar->findChild<QMenu*>(QStringLiteral("View"))) {
        addToolbarByLexicon(tb, viewMenu, QStringLiteral("11;"));
        addToolbarByLexicon(tb, viewMenu, QStringLiteral("19;"));
    }
}
```
This is a stylistic carry-over from the prior phase, not a new defect introduced by 06.5.

### IN-02: View menu lookup performed twice in the same function

**File:** `xvue/qt/src/xvue_qt_nlse_actions.cpp:264, 377, 454`
**Issue:** `mbar->findChild<QMenu*>(QStringLiteral("View"))` runs three times in `registerNlseActions_stub_`:
- Line 264 — `viewMenuForAnchor` for `ensureTopLevelMenu(insertBefore=...)`
- Line 377 — `viewMenu` for the View > Draw NLSE * extension block
- Line 454 — `viewMenu` for the toolbar `addToolbarByLexicon` calls

`findChild<T*>(name)` walks the QObject tree linearly; calling it three times for the same lookup is wasted work. Prior phases have the same shape so this is not a 06.5-introduced regression.
**Fix:** Cache the lookup once near the top of the function and reuse:
```cpp
auto* viewMenu = mbar->findChild<QMenu*>(QStringLiteral("View"));
// later, replace lines 377 and 454 conditionals with `if (viewMenu) { ... }`
```
Since this is per-window-build and runs exactly once per process via the `static bool registered` guard at line 201, the perf impact is negligible. Filing as Info / readability only.

### IN-03: Comment claim "20 qaction=yes" vs "19 qaction=yes" inconsistent across the same file

**File:** `xvue/qt/src/xvue_qt_nlse_actions.cpp:52-58`
**Issue:** The header comment says (line 52-58):
```
IN-04: every qaction=yes leaf in LEXICON-AUDIT-nlse.md is wired below.
       Verified one-to-one against the 20 qaction=yes rows:
       top-level: 1; 2; 5; 6; 11; 12; 13; 14; 15; 16; 19; (11)

```
The reconciliation in the parenthetical is correct, but a casual reader hits "20 qaction=yes rows" then "11+3+5 = 19" two lines later and has to re-read to disambiguate. The split between "audit-counted 20" and "this-TU-wires 19" is load-bearing — it is the same pattern that drove the 6.4 IN-04 comment.
**Fix:** Tighten the lead sentence to mention the split up front:
```
// IN-04: this TU wires 19 of the 20 audit-counted qaction=yes nlse leaves
//        (the 20th -- 99; SAVE & QUIT -- is owned by the shared 6.0
//        actQuit_ action; Plan 03 rewires its handler to queueLexicon).

//        ...
```

### IN-04: testBilingualLabelsEnglish silently passes when MEFISTO env is unset in CI

**File:** `xvue/qt/tests/test_xvue_qt_nlse_menu.cpp:302-313`
**Issue:** The slot QSKIPs cleanly on three preconditions (MEFISTO env empty, `td/m/anglais` missing, `td/ma/debunlse` missing). The comment on line 299-301 explicitly says this is intentional ("does NOT mock the filesystem because mocking would not catch real-install regressions"). However, in a CI environment that does not export `MEFISTO`, the slot will always QSKIP, and the EN-parser regression guard becomes inert — the same blind-spot flagged in the prior phases' reviews. The local dev environment has `MEFISTO=/home/mefisto/git/mefisto`, the bilingual files are present, and the slot does exercise the EN path; this is purely a CI-discipline concern.
**Fix:** No code change required for this phase. Recommend the operator running `xvue_qt_nlse_menu_tests` confirm that `testBilingualLabelsEnglish` reports `PASS` (not `SKIP`) in the local run log, or add a future enhancement that fails the test when `MEFISTO` is unset on a developer machine (distinguishable from CI by, e.g., the presence of `~/.config/LJLL/`). Same Info-level observation as 6.4 IN-05.
