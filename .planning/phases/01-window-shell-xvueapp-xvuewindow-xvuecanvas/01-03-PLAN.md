<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fortran ↔ C++ FFI | `CALL XVINITGRAPHIQUE` / `CALL XVFERMER` cross from Fortran into the Qt C++ layer via trailing-underscore symbols |
| User desktop session ↔ Qt platform plugin | `pp/ppxvtest0_qt` requires a valid `DISPLAY` / `WAYLAND_DISPLAY` — runs only in an interactive session |

## STRIDE Threat Register

Desktop-only FFI layer; primary threats are memory safety at the C++/Fortran boundary and Qt main-thread invariant violations. No network, no untrusted input, no authentication.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering (build regression) | Legacy X11 `bin/cbl_tout` path | mitigate | Task 3 step 1 runs the legacy build first and checks all 5 original binaries still exist — CLAUDE.md build-never-breaks rule |
| T-03-02 | Denial of Service | `QT_QPA_PLATFORM` missing or headless session | accept | D-21 requires a real desktop session; the human verifier is responsible for running the test in an X11/Wayland environment. Documented in Pitfall 11 of 01-RESEARCH.md. |
| T-03-03 | Elevation (reopen crash) | Second XVINITGRAPHIQUE call | mitigate | The driver deliberately exercises this path twice; `call_once` guards QApplication and xvfermer_ only resets the window slot |
</threat_model>
