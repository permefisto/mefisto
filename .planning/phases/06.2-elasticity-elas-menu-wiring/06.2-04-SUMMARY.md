## Decisions Made

- **Helper duplication preserved (not hoisted):** ensureTopLevelMenu is intentionally copy-pasted across elas/mail (per 06.2-02 patterns-established). Updated in lockstep this plan; a future refactor may hoist to a shared header (e.g., `xvue_qt_menu_helpers.h`) but is explicitly out of scope here. The two-line edit in lockstep is the explicit ask, and matching them by hand is lower-risk than introducing a new shared header that 6.3/6.4/6.5 would also need to wire.
- **Manual QMenu construction over addMenu(QString):** `mbar->addMenu(QString)` creates AND appends in one call — there is no Qt API to create-without-append. Constructing `new QMenu(title, mbar)` directly gives us control over the insertion site (`mbar->insertMenu(anchor->menuAction(), m)`); the QMenu parent is `mbar` so Qt's parent-child tree handles deletion just like `addMenu` would have.
- **testMenuOrder filters on non-null QAction::menu():** the slot tolerates dynamically-added separators (which have null menu()) so 6.3/6.4/6.5 can extend the menubar with separators without breaking the index assertion. The assertion locks only the FIRST FOUR top-level menus (the contract surface).
