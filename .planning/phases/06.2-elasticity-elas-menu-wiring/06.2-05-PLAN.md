<objective>
Fix Gap 2 from `06.2-HUMAN-UAT.md`: elas-specific menu/leaf labels remain FR even when `$MEFISTO/td/m/anglais` is present and `xvueIsEnglish()` returns true.

**Root cause** (verified by reading `xvue_qt_menu_file_parser.cpp:35-83` + `td/m/`):
- `XvueMenuFileParser::loadFor(name)` reads only `$MEFISTO/td/m/<name>`.
- The MEFISTO install installs ONE language into `td/m/` (FR or EN, copied from `td/mf/` or `td/ma/` respectively at install time). The `td/m/anglais` marker is supposed to indicate which.
- On the test rig, `td/m/anglais` IS present (Fortran banner reads "Mefisto speaks ENGLISH") but `td/m/debuelas` still contains the FR text — meaning the install was incomplete OR the marker is stale OR the user toggled the flag without re-installing the menu tree.
- Empirically: `td/ma/debuelas` carries the canonical EN labels ("ELASTICITY INPUT DATA", etc.) and `td/mf/debuelas` carries the FR labels.

**The generalized fix** (per gap-closure scope explicit "fix must generalize via the audit parser, not hard-code per module"):

Make `XvueMenuFileParser::loadFor()` language-aware. When `xvueIsEnglish()` returns true AND `td/ma/<name>` is readable, parse THAT file. Otherwise fall through to `td/m/<name>` (current behavior). This change is at a single point and benefits every module that consumes the parser: 6.1 mail, 6.2 elas, and the upcoming 6.3/6.4/6.5 flui/ther/nlse waves.

The shared 6.0 chrome strings (File menu title, Open Project…, etc.) already render correctly because they go through `xvueT(MsgId::*)` which consults the in-source `kTable` keyed on `xvueIsEnglish()`. The bug is exclusively in the menu-file parser branch used by per-module action TUs that read FR-only menu titles via `XvueMenuFileParser::loadFor("<menu>")`.

A new QTest slot (`testBilingualLabelsEnglish`) sets `MEFISTO` to point at the real tree, ensures `td/m/anglais` exists, clears the parser cache, and asserts that `debuelas.label(2)` == `"ELASTICITY INPUT DATA"`. The test deliberately exercises the `td/ma/` path so future regressions (e.g., 6.4 ther refactoring the parser) cannot ship.

Purpose: lock the bilingual contract specified by UX-08 + ROADMAP Phase 6.0 success criterion #4 ("xvueIsEnglish() reads $MEFISTO/td/m/anglais file-existence and all shared chrome renders in FR or EN accordingly") — extending it from "shared chrome" to "per-module menu file parser" as required by UX-05 (per-module slice).
Output: 2 modified parser files, 1 new QTest slot, full serial Qt+X11 rebuild green, 126/0/2 test totals.

          ```cpp
          const MenuFile& XvueMenuFileParser::loadFor(const QString& name) {
              auto& c = cache();
              auto it = c.find(name);
              if (it != c.end()) return *it;

              MenuFile mf;

              const QByteArray mefisto = qgetenv("MEFISTO");
              if (mefisto.isEmpty()) {
                  // Insert empty MenuFile so we don't retry on every call.
                  return *c.insert(name, mf);
              }

              const QString home = QString::fromLocal8Bit(mefisto);

              // 06.2 Plan 05 gap-2 fix: when xvueIsEnglish() is true, prefer
              // $MEFISTO/td/ma/<name> (the canonical EN tree) over the
              // generic td/m/<name> (which often holds whichever language
              // the install copied at setup time, regardless of the flag's
              // current state).
              //
              // The probe is cheap because xvueIsEnglish() caches its
              // result via static-local initialisation in xvue_qt_i18n.cpp.
              QString chosen_path;
              if (xvueIsEnglish()) {
                  const QString en_path = home + QStringLiteral("/td/ma/") + name;
                  if (QFile::exists(en_path)) {
                      chosen_path = en_path;
                  }
              }
              if (chosen_path.isEmpty()) {
                  chosen_path = home + QStringLiteral("/td/m/") + name;
              }

              QFile f(chosen_path);
              if (!f.open(QIODevice::ReadOnly | QIODevice::Text)) {
                  return *c.insert(name, mf);
              }

              QTextStream ts(&f);
              QString content = ts.readAll();

              // Title regex — capture the FIRST single-quoted string after
              // `variable <TAG>`. Per RESEARCH §Pattern 2 grammar.
              static const QRegularExpression titleRx(
                  QStringLiteral(R"(variable\s+\S+\s+'((?:[^']|'')*)'\s+entier)"),
                  QRegularExpression::CaseInsensitiveOption);
              auto tm = titleRx.match(content);
              if (tm.hasMatch()) {
                  mf.title_ = tm.captured(1)
                               .replace(QStringLiteral("''"), QStringLiteral("'"));
              }

              // Pair regex — <digits> : '<label>' repeated. RESEARCH Pitfall 5
              // says td/m/modifm2d has a typo `80;` — we accept ONLY `:` as the
              // separator so the typo row falls back to "80;" via MenuFile::label().
              static const QRegularExpression pairRx(
                  QStringLiteral(R"((\d+)\s*:\s*'((?:[^']|'')*)')"));
              auto mi = pairRx.globalMatch(content);
              while (mi.hasNext()) {
                  auto m = mi.next();
                  int code = m.captured(1).toInt();
                  QString label = m.captured(2)
                                   .replace(QStringLiteral("''"),
                                            QStringLiteral("'"));
                  mf.labels_.insert(code, label);
              }

              return *c.insert(name, mf);
          }
          ```
