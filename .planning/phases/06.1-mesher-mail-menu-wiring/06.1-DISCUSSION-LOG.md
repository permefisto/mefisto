## Submenu mapping

### Q5: QAction ↔ LIMTCL mapping strategy

| Option | Description | Selected |
|--------|-------------|----------|
| Tiered push | Top-level QAction pushes numeric code; Fortran sub-prompt runs as text | |
| Flat QActions for leaf commands | Each leaf is its own QAction; ~30-40 total | ✓ |
| Full nested QMenu tree | Mirror entire Fortran tree as QMenus; 60+ QActions | |

**User's choice:** "Flat QActions for leaf commands and also keep the text
driven, user can do like he wants." (free-text via Other).
**Interpretation:** Flat leaf QActions as option B, with explicit
reaffirmation that typed lexicon continues to work for every command path
(already a D-03/D-04 invariant from Phase 6.0 — user reiterated the
co-existence expectation).
