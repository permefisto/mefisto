## Decisions Made

### Architectural
- **Weak-symbol hoist:** the 6.0 layout put the 5 `register<Mod>Actions_stub_` inside `xvue_qt_api.cpp`'s anonymous namespace, which gave them *internal* linkage and silently invalidated the weak-override pattern everyone downstream assumed. Hoisted them out and marked them `extern "C"` + `__attribute__((weak))`. Plans 6.2–6.5 now have a working pattern; no further api.cpp edits are needed when they ship their `xvue_qt_<mod>_actions.cpp` TUs.
- **verify_abi filter:** rather than bump the header-declared ABI to 59, we exclude the register-stub pattern from the T-symbol count. These symbols are internal dispatch helpers, not Fortran entry points; they never appear in `xvue_qt_api.h`.
- **Toolbar 4-of-5 here, 5th in Plan 03:** the 99; Save&Quit toolbar entry requires rewiring the existing 6.0 `actQuit_` handler through `queueLexicon`. That touches `xvue_qt_window.cpp` which is squarely inside Plan 03's scope (with `closeEvent`). Plan 02 stops at the 4 mesh/view toolbar additions.

### Semantic / UX
- **Label fallback = lexicon-path string:** when a menu file is missing or a row is malformed (e.g. the `td/m/modifm2d` `80;` typo), `MenuFile::label(N)` returns `"N;"` instead of a cryptic blank. This keeps every QAction self-identifying even under failure.
- **[menu] echo before queue:** ordering enforced in the lambda — `dock->appendLine("[menu] 1;1;")` runs synchronously on the main thread before `mb->queueLexicon("1;1;")`, so the console always shows the typed-equivalent before Fortran consumes the characters.
- **SVG palette-awareness:** all 10 icons use `stroke="currentColor"` so they track the user's Qt palette (light → dark mode flip costs zero SVG edits).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Hoist register<Mod>Actions_stub_ out of anonymous namespace**
- **Found during:** Task 2 (preparing the strong-symbol body)
- **Issue:** The plan describes a weak-symbol override pattern where `xvue_qt_mail_actions.cpp` declares `extern "C" void registerMailActions_stub_(...)` and the linker resolves the stronger definition over the stub in `xvue_qt_api.cpp:75`. But `grep` confirmed the 6.0 scaffold put those stubs INSIDE the anonymous namespace opened at `xvue_qt_api.cpp:49` — anonymous namespace gives them internal linkage, making them invisible to the linker outside the TU. A strong definition in another TU in the same archive would either (a) not be found when api.cpp's dispatch calls `registerMailActions_stub_` (unresolved symbol), or (b) trigger multiple-definition errors if the linker did resolve both.
- **Fix:** Moved the five `register<Mod>Actions_stub_` declarations + definitions OUT of the anonymous namespace, placed them at file scope with `extern "C"` linkage and `__attribute__((weak))`, leaving the 5 `warn_register_*_done_` flags inside the anonymous namespace. The dispatch call at `xvue_qt_api.cpp:1486` needs no change — it calls the symbols by their unadorned C name from inside the existing `extern "C" {` block.
- **Files modified:** `xvue/qt/src/xvue_qt_api.cpp`
- **Verification:** `nm libxvueqt.a | grep registerMailActions_stub_` now shows one `W` (weak stub) in `xvue_qt_api.cpp.o` and one `T` (strong body) in `xvue_qt_mail_actions.cpp.o`; elas/flui/ther/nlse stay `W`.
- **Committed in:** `0dbdb57` (Task 2 commit)

**2. [Rule 3 — Follow-up] Filter register<Mod>Actions_stub_ from verify_abi.sh T-count**
- **Found during:** Task 2 (post-fix analysis of the ABI invariant)
- **Issue:** With the stubs hoisted to external linkage + Plan 02's mail strong body, the raw `nm libxvueqt.a | grep ' T ..._$'` count increases by 1 (from 58 to 59). The 58-entry invariant comes from `xvue_qt_api.h` which declares only the Fortran-facing entries — `register<Mod>Actions_stub_` are NOT in that header. Without a filter, `verify_abi` would fail the build with "ERROR: ABI symbol count drift" the moment Plan 02 lands.
- **Fix:** Added a `grep -v ' T register[A-Z][a-zA-Z]*Actions_stub_$'` stage to the pipe in `verify_abi.sh`. Documented the reasoning in the script comments.
- **Files modified:** `xvue/qt/cmake/verify_abi.sh`
- **Verification:** full `bin/cbl_tout_qt` build emits `verify_abi: nm count: 58  header count: 58` — invariant preserved end-to-end.
- **Committed in:** `0dbdb57` (Task 2 commit — same logical fix as #1)

**3. [Rule 3 — Blocking] Reverted build-artifact file churn before commit**
- **Found during:** Task 3 (`git status` after running `bin/cbl_tout_qt`)
- **Issue:** `bin/cbl_tout_qt` regenerates `elas/lib`, `flui/lib`, `mail/lib`, `reso/lib`, `ther/lib`, `util/lib`, `xvue/lib`, and `incl/homdir.inc`. These are build outputs, not source. Committing them would pollute the tree diff.
- **Fix:** `git checkout --` on those paths before the Task 3 commit so only the intentional Plan 02 deliverables (10 SVGs + qrc append) landed in the commit. The `.lib` files will regenerate on any subsequent build.
- **Files modified:** (revert only — no tracked change)
- **Verification:** `git show 8491756 --stat` shows only 11 new files (10 SVGs + qrc edit), no `.lib` churn.
- **Committed in:** (pre-commit cleanup for `8491756`)
