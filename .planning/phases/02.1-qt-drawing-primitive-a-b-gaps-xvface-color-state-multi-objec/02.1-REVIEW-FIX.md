## Fixed Issues

### IN-02: Palette clamp/rebuild logic triplicated

**Files modified:** `xvue/qt/src/xvue_qt_api.cpp`
**Commit:** `2639d8c`
**Applied fix:** Extracted the palette-index clamp + dirty-cache rebuild pattern
into a file-local static helper `palette_resolve(int icolor, int fallback)`
returning `const QColor&`. Refactored the three call sites:

- `proc(xvcouleur)`: `st->foreground_ = palette_resolve(*icolor, 1)` (legacy red fallback), followed by existing `applyPen()`.
- `proc(xvfond)`: `st->background_ = palette_resolve(*icolor, 0)` (legacy black fallback), followed by existing fillRect.
- `apply_palette_foreground(st, icolor)`: now a two-line wrapper that calls `palette_resolve(icolor, 1)` and `applyPen()`.

The helper is `static` (file-local), consistent with the existing `apply_palette_foreground`. All three sites now share the same clamp/rebuild semantics, so future palette-cache policy changes (alpha, gamma, etc.) only touch one place.

### IN-01: Dead pen restore between fill and outline steps

**Files modified:** `xvue/qt/src/xvue_qt_api.cpp`
**Commit:** `9f3057c`
**Applied fix:** Chose the stronger option from the review (drop the dead code
rather than only updating the comment). Removed the `QPen saved_pen_after_ncf = st->painter_->pen();` capture and the matching `st->painter_->setPen(saved_pen_after_ncf);` restore in `xvfacetraits_`. Both were immediately superseded by the next `apply_palette_foreground(st, *nca)` call, which invokes `XvueState::applyPen()` and unconditionally rebuilds `pen_` from `pen_style_ + foreground_` (see `xvue_qt_state.cpp:136-142`).

Updated the surrounding comment block to correctly attribute dashed-style
survival to `pen_style_` being threaded through `applyPen()` on every
`apply_palette_foreground()` call (not to the now-removed pen save/restore).
Added an inline IN-01 note explaining why no restore is needed between the
fill and outline steps.

### IN-03: Brush-restore comment partially stale

**Files modified:** `xvue/qt/src/xvue_qt_api.cpp`
**Commit:** `e5b55fd`
**Applied fix:** Rewrote the comment block above the final
`st->painter_->setBrush(QBrush(st->foreground_, Qt::SolidPattern))` so the
contract statement and the WR-04 tightening are no longer adjacent
contradictions. New text (IN-03 / WR-04 tag) states plainly that:

1. Legacy leaves `foreground_` at `nca` (matched by not touching `foreground_`).
2. The outline step left the painter brush at `Qt::NoBrush`, which would be refreshed by any subsequent `xvcouleur_/applyPen()` call.
3. WR-04 tightens the post-condition by restoring the brush here so primitives that read the live painter brush directly (e.g. `xvface_`) see the canonical post-`ncf`->`nca` final state without depending on an intervening state-change call.

No behavioural change — only the comment was rewritten.
