## Decisions Made

1. **File-local helper instead of repeated `proc(xvcouleur)` calls** (RESEARCH.md Pitfall 1). Calling `proc(xvcouleur)` twice from inside `xvfacetraits_` would re-enter `XvueApp::ensure()`, `XVUE_QT_ASSERT_MAIN_THREAD()`, and the window-slot lookup twice per face draw. The helper has internal linkage (`static`), no exports, no header entry, ≤12 lines, and is unit-testable by inspection because its body is a verbatim subset of `xvcouleur_` lines 354-371.

2. **Dashed-pen symptom is a downstream artifact, not a separate bug.** RESEARCH.md identified that `applyPen()` already rebuilds the `QPen` from `pen_style_ + foreground_`. As long as the helper goes through `applyPen()` (it does), the dashed style installed by `xvtypetrait_` is preserved across both color switches and the outline step inherits it automatically. Confirmed visually in the post-fix `xvtest4_qt_xcb.png` (magenta dashed cube edges present).

3. **Defensive `setBrush(QBrush(foreground_, SolidPattern))` at function exit.** Legacy `xvue/xvuelc.c::xvfacetraits_` leaves the X11 GC in a loose state at exit (foreground at nca, fill style unchanged). Qt's `QPainter` is more state-sensitive: leaving brush at `Qt::NoBrush` would surprise downstream primitives that call `painter_->brush()` directly. The defensive restore costs one `setBrush` call and keeps the post-call state canonical.

4. **No changes to `xvuelc.c`, `xvouvrir.f`, or `xvue_qt_api.h`.** Preserves BUILD-07 (legacy bit-identity), VALID-02 (Fortran ABI symmetry), and the 57-export ABI freeze. Verified by `diff -q` against `git show HEAD:` for each file.
