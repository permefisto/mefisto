# Phase 03.1 Summary — xvtest1..4 Driver Infrastructure on Both Backends

**Date completed:** 2026-04-12

**03-04 is now unblocked.**

## Objective (recap)

Phase 3 A/B validation (plan 03-04) needs the `pp/ppxvtest{1..4}{,_qt}` driver
executables present on both the Qt 6 and legacy X11 backends. Research for
Phase 3 showed these binaries had never been built on the legacy side
(`bin/cbxvtest*` legacy scripts missing) and the Qt side crashed in the
very first `XVOUVRIR` call because `xtinit_` was a warn-once stub.

Phase 03.1 is three waves of build-infrastructure + one small Qt-side fix:
it does NOT add any new runtime feature to the xvue library.

## Deliverables

### Wave 0 — Plan 01: Qt xtinit_ forwarding fix

- `xvue/qt/src/xvue_qt_api.cpp`: `xtinit_` promoted from warn-once stub to
  `proc(xvinitgraphique)()` forwarding body. Idempotency preserved via
  `window_slot()`'s lazy alloc.
- A6 verified: only `prpr/xvtest{1,2,3,4}.f` call `XVOUVRIR` in `prpr/`;
  `prpr/xvtest0.f` uses `XVINITGRAPHIQUE` directly; `xvue/xvouvrir.f` is
  unchanged (`CALL XTINIT; CALL XVINIT`).
- BUILD-07 X11 bit-identity preserved (xvue/xvuelc.c + xvouvrir.f untouched).
- ABI: 57 symbols (verify_abi header==library==57); `xtinit_` exported once.

### Wave 1 — Plan 02: 9 new build scripts + 2 top-level edits

- **New Qt scripts:** `bin/cbxvtest{1,2,3,4}_qt` (generated from the
  pre-existing `bin/cbxvtest0_qt` via sed).
- **New legacy scripts:** `bin/cbxvtest{0,1,2,3,4}` (Pitfall 6 closed —
  legacy `cbxvtest0` was also missing). Link pattern: `util/lib xvue/lib
  xvue/xvuelc.o -lgfortran -L/usr/X11R6/lib64 -lX11`, with `mail/lib`
  intentionally dropped (xvtest drivers exercise xvue only).
- **bin/cbl_tout_qt:** 5 new lines invoking `cbxvtest{0..4}_qt` after `cbnlse_qt`.
- **bin/cbl_tout:** 5 new lines invoking `cbxvtest{0..4}` after `cbpoba`.
- Full rebuilds of both top-level drivers green; all 10 `ppxvtest{0..4}{,_qt}`
  executables produced; pre-existing solver executables preserved.

### Wave 2 — Plan 03: Hardened smokes + plan 03-04 patch + operator notes

- **5/5 Qt drivers** pass hardened headless smoke with
  `QT_QPA_PLATFORM=offscreen timeout --preserve-status 5s` (30 s for
  xvtest0_qt due to embedded SLEEP(10)+SLEEP(3)). No warn-once for
  `xtinit_` or any Phase 3 entry point.
- **Bug fix:** `xvinfo_` no longer writes `*maxfonts`. The Fortran caller
  passes `PARAMETER(MAXFONTS=512)` which under `gfortran -O` lands in
  read-only memory — writing through it SIGSEGV'd at the first
  `XVOUVRIR → XVINIT → XVINFO` chain on Qt (ppxvtest1..4_qt). This was
  not caught in Plan 01 because ppxvtest0_qt bypasses xvinit.f. The
  legacy C backend (`xvue/xvuelc.c:612`) never wrote `*maxfonts`; the
  Qt impl now matches.
- **Legacy smoke:** 3/5 drivers non-crash (xvtest{2,3,4}); 2/5 crash in
  pre-existing `xvue/xvuelc.c` bugs (xvtest0 in `xvtypetrait_`, xvtest1
  in `xvnbpixeltexte_`). Both are out-of-scope for Phase 03.1 and
  tracked in `deferred-items.md`.
- **03-04 Task 1 patch:** timeout wrapper, enriched warn-once grep
  (adds `xtinit` alternation), exit code tolerance `{0, 124, 143}`,
  xvtest1 `PROBLEME AVEC LA SOURIS` note-without-fail, operator-notes
  pointer to `03.1-NOTES.md`.
- **03.1-NOTES.md:** operator brief for the 03-04 Task 2 human A/B gate,
  covering Pitfalls 1-4, the xvinfo_ fix root cause, and the legacy
  crash map.

## BUILD-07 / VALID-02 Preservation Statement

- **BUILD-07 (legacy X11 bit-identity):** `xvue/xvuelc.c` and `xvue/xvouvrir.f`
  were NOT modified. `xvue/qt/include/xvue_qt_api.h` was NOT modified. The
  only files touched across all three plans are:
  - `xvue/qt/src/xvue_qt_api.cpp` (Plans 01 + 03 — two small fixes)
  - `bin/cbxvtest{0..4}{,_qt}` (Plan 02 — new build scripts)
  - `bin/cbl_tout{,_qt}` (Plan 02 — 5 new lines each)
  - `.planning/**` (all docs)
  - `.planning/phases/03-text-fonts-colormap/03-04-PLAN.md` (Plan 03 patch)
- **VALID-02 (A/B regression discipline):** Qt backend now opens real
  windows via `xtinit_` and survives the full `XVOUVRIR → XVINIT → XVINFO
  → XVCHARGEFONTE → XVTEXTE → ...` chain. Pre-existing legacy bugs are
  out-of-scope and tracked for a later Phase 3 follow-up.

## Key decisions

- **D-03.1-01:** Direct forwarding `xtinit_ → xvinitgraphique_` chosen over
  duplicating the 20-line exposure pump — automatic parity if the pump is
  tuned later.
- **D-03.1-02a:** Legacy xvtest link pattern omits `mail/lib` (drivers
  exercise xvue only, no mesher archive needed).
- **D-03.1-02b:** Qt scripts generated via sed from `cbxvtest0_qt` — sed is
  a generation tool only; the 4 files are committed explicitly per project
  convention.
- **D-03.1-02c:** Top-level driver edits use the Edit tool (literal
  replace) instead of `sed -i a\\` to avoid the `$MEFISTO` shell-variable
  quoting foot-gun.
- **D-03.1-02d (Pitfall 6):** `bin/cbxvtest0` (legacy) created
  symmetrically with `bin/cbxvtest0_qt` — research found it was missing.
- **D-03.1-03a:** `xvinfo_` no longer writes `*maxfonts`. Matching legacy
  `xvuelc.c:612` contract is both correct and safe under gfortran -O with
  Fortran PARAMETER actuals.
- **D-03.1-03b:** 03-04 smoke exit code tolerance expanded to `{0, 124, 143}`
  to match `timeout --preserve-status` signal-forwarding behaviour on Linux.
- **D-03.1-03c:** Legacy xvtest{0,1} pre-existing crashes are out of scope
  for Phase 03.1 and tracked in `deferred-items.md`.
