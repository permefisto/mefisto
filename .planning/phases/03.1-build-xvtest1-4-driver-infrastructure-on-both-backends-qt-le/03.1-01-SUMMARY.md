# Phase 03.1 Plan 01: Unblock Qt-side XVOUVRIR → XTINIT Path Summary

**One-liner:** Promoted the Qt backend's `xtinit_` stub to a real window-open body by forwarding to `xvinitgraphique_`, unblocking Phase 03.1's xvtest1..4 drivers without touching the X11 backend.

## What Was Delivered

- **Task 1 (read-only A6 verification):** grep assertion confirmed only `prpr/xvtest{1,2,3,4}.f` contain `CALL XVOUVRIR`; `prpr/xvtest0.f` uses `CALL XVINITGRAPHIQUE` (not XVOUVRIR); `xvue/xvouvrir.f` is still the "CALL XTINIT; CALL XVINIT" wrapper. Blast radius of the Qt-side fix is bounded to xvtest1..4 as research claimed.

- **Task 2 (code fix):** `xvue/qt/src/xvue_qt_api.cpp` `xtinit_` body replaced — previously a `warn_once(warned, "xtinit_")` stub, now calls `proc(xvinitgraphique)()` directly. Extensive in-file comments explain Pitfall 1, the idempotency guarantee via `window_slot()`'s lazy alloc, and that X11 remains untouched. Commit: `63450c5`.

### Auto-fixed Issues

**1. [Rule 3 - Blocking] xvtest0_qt smoke-test timeout too tight**
- **Found during:** Task 2, Step 6
- **Issue:** Plan specified `timeout --preserve-status 10s pp/ppxvtest0_qt`, but `prpr/xvtest0.f` contains `CALL SLEEP(10)` + `CALL SLEEP(3)` = 13 s minimum wall time, so the 10 s ceiling caused `SIGTERM` (exit 143) and a spurious "regression."
- **Fix:** Used 30 s timeout instead. Clean exit 0. This is a plan-text bug, not a code bug — the plan was authored before knowing xvtest0's embedded SLEEPs.
- **Files modified:** none (test command only)
- **Commit:** n/a

**2. [Rule 1 - Plan spec drift] ABI count acceptance criterion is stale (34 vs 57)**
- **Found during:** Task 2, Step 5
- **Issue:** Plan acceptance criterion "ABI count 34" reflects an older scaffolding state. Current `xvue/qt/CMakeLists.txt` ships a `verify_abi` target that counts symbols and compares them against the declarations in `xvue/qt/include/xvue_qt_api.h` — the authoritative invariant. - **Fix:** Deferred to the authoritative check (`verify_abi` target) instead of the hard-coded "34". `verify_abi` passed as a normal build step, and `xtinit_` still appears exactly once. The plan's "34" number should be revised in the next plan refactor.
