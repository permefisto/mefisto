# Phase 03.1: Code Review Report

**Reviewed:** 2026-04-12
**Depth:** standard
**Files Reviewed:** 12
**Status:** issues_found

## Summary

Phase 03.1 adds five legacy-X11 driver scripts (`cbxvtest0`..`cbxvtest4`), four new
Qt driver scripts (`cbxvtest1_qt`..`cbxvtest4_qt`), and wires both top-level
build scripts (`cbl_tout`, `cbl_tout_qt`) to invoke the new drivers. The single
source file in the Qt API (`xvue/qt/src/xvue_qt_api.cpp`) is in scope because
Phase 03.1 touches it indirectly through the BUILD-07 bit-identity constraint;
no Phase 03.1 code edits were made to that file — it is reviewed as context.

**Scope-sensitive finding:** the most load-bearing change is the new
`xvue_qt_api.cpp:266-283` comment + fix for `*maxfonts`. That bug fix is
correct and matches the legacy xvuelc.c contract (pure input/capacity).

No critical issues were found. The three warnings concern robustness of the
new Qt build drivers — they fail silently rather than loudly when pkg-config
is missing, when `$MEFISTO` is unset, and when intermediate build steps fail.
These are acceptable for development but should be hardened before release.
The six info items are stale boilerplate comments and minor dead-store /
inconsistency issues.

The X11 drivers (`cbxvtest0..4`) are byte-level faithful copies of the
pre-existing `cbmail` pattern with `mail/lib` removed — this preserves
BUILD-07 bit-identity of the legacy compile/link pipeline. Good.

The Qt drivers (`cbxvtest{1..4}_qt`) correctly omit `ccxvue` and `xvuelc.o`
and link `libxvueqt.a` + `pkg-config --libs Qt6…` + `-lstdc++` — matching
the established Qt backend link recipe.

## Warnings

### WR-01: `cbxvtest{1..4}_qt` silently link-fails when pkg-config is missing

**Files:**
- `bin/cbxvtest1_qt:37`
- `bin/cbxvtest2_qt:37`
- `bin/cbxvtest3_qt:37`
- `bin/cbxvtest4_qt:37`

**Issue:** `QT_LIBS=$(pkg-config --libs Qt6Widgets Qt6Gui Qt6Core Qt6PrintSupport)`
captures stdout only. If `pkg-config` is not installed or the Qt6 `.pc` files
are missing, the command prints a diagnostic to stderr, returns non-zero, and
leaves `QT_LIBS` empty. The subsequent `gfortran … $QT_LIBS -lstdc++ …` then
fails with cryptic undefined-symbol errors instead of a clear "Qt6 not found"
message. The CLAUDE.md rule "Asking before acting — if a C include or an
Ubuntu system package is missing to compile, ask the user to install it"
makes this worth hardening.

**Fix:** Gate the capture and exit loudly on failure:

```bash
if ! QT_LIBS=$(pkg-config --libs Qt6Widgets Qt6Gui Qt6Core Qt6PrintSupport 2>&1); then
    echo "pkg-config could not locate Qt6 (.pc files missing?). QT_LIBS='$QT_LIBS'" >&2
    echo "Install qt6-base-dev / qt6-tools-dev and retry." >&2
    exit 1
fi
```

Note: `bin/cbl_tout_qt:56-67` already applies this "exit on CMake failure"
pattern — the xvtest drivers should match.

### WR-02: `cbl_tout_qt` destructive `rm -rf` is unguarded against unset `$MEFISTO`

**File:** `bin/cbl_tout_qt:51`

**Issue:** `rm -rf $MEFISTO/xvue/qt/build` is executed with no prior check that
`$MEFISTO` is set and non-empty. If the user forgot the env var from CLAUDE.md,
this expands to `rm -rf /xvue/qt/build` — harmless on most hosts but nonzero
blast radius. Line 89 `rm $MEFISTO/*/*.o` has the same issue, as does
`bin/cbl_tout:72`. This is a legacy pattern, not introduced by Phase 03.1,
but the new Qt top-level script is a good place to break the pattern.

**Fix:** Add a guard near the top of `cbl_tout_qt` (before the first rm):

```bash
: "${MEFISTO:?MEFISTO is not set — source the environment (see CLAUDE.md)}"
```

This is a bash parameter-expansion idiom that aborts with a message if the
variable is unset or empty. Zero runtime cost.

### WR-03: `cbxvtest{0..4}` X11 drivers ignore `gfortran` exit status

**Files:**
- `bin/cbxvtest0:42-44`
- `bin/cbxvtest1:42-44`
- `bin/cbxvtest2:42-44`
- `bin/cbxvtest3:42-44`
- `bin/cbxvtest4:42-44`

**Issue:** The drivers test `if test -f $nompp` as a success proxy for the
gfortran link step. If `$nompp` already existed from a previous build and
the new gfortran invocation silently fails (e.g., missing `xvue/lib` archive),
the test passes and the driver reports "CORRECT to execute" against a stale
binary. Line 36-39 does delete `$nompp` first, so the immediate risk is
bounded — but if the unlink itself fails (read-only `pp/`, permissions),
the stale-binary misreport resurfaces.

This is consistent with the legacy `cbmail` pattern, so it is not a
regression. Flagged because the cb* scripts are now driving a Qt/X11
parity matrix where a silent false-positive "CORRECT" is meaningfully
worse than in a single-backend world.

**Fix:** Capture gfortran exit status explicitly:

```bash
gfortran -Wall -mcmodel=large -m64 -O -fopenmp -I. prpr/xvtest0.f \
     util/lib xvue/lib xvue/xvuelc.o \
    -lgfortran -L/usr/X11R6/lib64 -lX11 -o $nompp
rc=$?
if [ $rc -ne 0 ]; then
    echo "gfortran link FAILED (rc=$rc) — $nompp is not updated" >&2
    exit $rc
fi
```

The same fix applies to the `_qt` variants (lines 39-42 in each).

### IN-03: Dead store of `QWindow* wh` in `xvinitgraphique_`

**File:** `xvue/qt/src/xvue_qt_api.cpp:165`

**Issue:** `QWindow* wh = win->windowHandle();` is assigned, then immediately
overwritten inside the loop at line 169 (`wh = win->windowHandle();`) before
its first use. The initial assignment is dead code.

**Fix:** Either drop the initial assignment and declare `QWindow* wh = nullptr;`,
or hoist it to the outer scope only if some caller needs it after the loop
(none does). Minor cleanup, no behavioural change.

```cpp
QWindow* wh = nullptr;
while (t.elapsed() < timeout_ms) {
    QCoreApplication::processEvents(
        QEventLoop::ExcludeUserInputEvents, 20);
    wh = win->windowHandle();
    if (wh && wh->isExposed()) break;
}
```

### IN-04: `xvtrait_` / `xvtraits_` / `xvface_` do not guard on `st->backing_`

**File:** `xvue/qt/src/xvue_qt_api.cpp:644, 663, 591`

**Issue:** `xvue_qt_draw_text_common` (line 86) checks `!st->backing_` before
drawing, but `xvtrait_` / `xvtraits_` / `xvface_` / `xvfacetraits_` /
`xvfond_`'s draw branches / rectangle common helper only check
`painter_->isActive()`. In practice an active painter implies a valid
device, so this is defensive hardening rather than a bug fix — but the
inconsistency will confuse readers comparing the entry points.

**Fix:** Either add `!st->backing_` to every draw-path gate for consistency,
or document in a header comment that "`painter_->isActive()` implies
`backing_ != nullptr` under the single-backing invariant (02/D-05)". The
latter is preferable — no runtime cost, documents the Phase 2 invariant.

### IN-05: `cbl_tout_qt` asymmetric module coverage vs `cbl_tout`

**File:** `bin/cbl_tout_qt:91-100`

**Issue:** `cbl_tout` invokes `cbinit`, `cbmail`, `cbelas`, `cbther`, `cbflui`,
`cbnlse`, `cbpoba`, plus all five `cbxvtest*`. `cbl_tout_qt` omits `cbinit_qt`
and `cbpoba_qt` (they do not exist yet). A reader who scans only the top-level
script will not know whether this omission is intentional (Qt port incomplete)
or accidental. This is out of Phase 03.1 scope as a feature request, but the
asymmetry should be commented so future maintainers don't "fix" it by adding
broken invocations.

**Fix:** Add a comment near line 91:

```bash
# NOTE: cbinit_qt and cbpoba_qt do not exist yet — the Qt backend does not
# currently build ppinit or pppoba. Add them here when the Qt port lands.
$MEFISTO/bin/cbmail_qt
...
```

### IN-06: `cbl_tout:72` unconditional `rm $MEFISTO/*/*.o` races the just-built xvuelc.o

**File:** `bin/cbl_tout:72`

**Issue:** Line 50 invokes `ccxvue` to build `xvue/xvuelc.o`. Line 72 then runs
`rm $MEFISTO/*/*.o`, which matches and deletes `xvue/xvuelc.o`. Each downstream
`cb*` script then rebuilds it via its own `if !(test -f xvue/xvuelc.o); then
bin/ccxvue; fi` fallback (e.g. `cbxvtest0:30-33`), so the final link succeeds —
but the deletion makes line 50 pointless. This is pre-existing (not Phase 03.1),
but it's in-scope because `cbl_tout` is one of the files under review.

**Fix:** Either drop line 50 (let each cb* script lazy-build xvuelc.o) or
exclude `xvue/` from the wildcard:

```bash
# keep xvue/xvuelc.o which was built by ccxvue above
find $MEFISTO -maxdepth 2 -name '*.o' ! -path '*/xvue/xvuelc.o' -delete
```
