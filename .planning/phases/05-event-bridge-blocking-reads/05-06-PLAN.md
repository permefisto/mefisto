```
## Phase 5 — Event bridge

The Qt backend uses a nested QEventLoop inside XvueEventBridge::waitForEvent
to implement the blocking Fortran primitives (xvsouris_, xvsouris2_,
xvpause_). Motion events are coalesced via QTimer::singleShot(0, ...) so
fast mouse drags return only the tail of the burst, matching X11
XEventsQueued(QueuedAfterFlush) semantics.

### Known caveats

- deplsouris_ calls QCursor::setPos, which is a no-op on most pure-Wayland
  compositors. X11 (directly or via XWayland) is the supported session type
  for Phase 5 interactive workflows. Pure-Wayland users can still run
  headless capture scripts (MEFISTO_XVSOURIS_AUTOEXIT=1) and non-cursor-
  warping interactive sessions.

- The diagnostic motion counter emitted by the bridge is gated behind
  MEFISTO_XVSOURIS_DEBUG=1; set this env var to see per-waitForEvent event
  counts on stderr. Off by default.

- Phase 6 will layer a menu command queue on top of this bridge; modal
  dialogs will be gated by XvueApp::blockingDepth() > 0.
```
